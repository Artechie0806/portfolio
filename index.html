Multi-Agent LLM · Text-to-SQL · Data Visualization · Full Stack

DataScribe - Conversational Data Analyst

Upload any spreadsheet, CSV, or SQLite file and talk to it. DataScribe turns the file into a DuckDB warehouse, works out what every column means by measuring it, and answers questions in conversation — with a live chart whenever a chart says it better than a sentence.

Problem: Text-to-SQL tools assume a curated database and a hand-written data dictionary — pointed at an arbitrary uploaded file, they guess at column meanings and return confident wrong numbers.

PythonFastAPIDuckDBQwenSVG ChartsNDJSON Streaming
Results Built a seven-agent pipeline (Router → SQL author → critic → chart agent → narrator) over a two-pass profiler that derives every table's grain, column roles, joins, and quality flags at upload — no data dictionary. Model-authored SQL runs read-only behind a statement guard with row caps and timeouts, and every chart is deterministically reconciled against the actual result before rendering.

Multi-Agent LLM · Fact Verification · Local LLM · Full Stack

Fact-Checked Research Agent

A research agent that treats evidence as the product rather than the prose. It drafts atomic claims, then hands each one to a separate verifier that checks it against the source it cites — so every line of the report either carries a verbatim quote or is flagged as unsupported.

Problem: Agents that merely chain search APIs present fluent prose as fact — the same model that writes a claim also judges it, so hallucinations pass through unchallenged.

PythonFastAPIQwenDuckDuckGoTrafilaturaSSE
Results Built a Researcher → Verifier → Orchestrator pipeline that isolates the fact-checker — it sees only a claim and its cited text, and must extract a supporting quote that is then located in the original by string search, with the verdict downgraded automatically when it isn't found. Every call runs inside a 16k-token budget; reports ship with grounding rate, verdict breakdown, and real token counts.

Local Voice RAG Assistant

Ask questions about your own documents by voice or by text, entirely offline. Speech goes in, a grounded answer with citations comes back, and nothing leaves the machine.

Problem: Voice assistants over private documents normally mean shipping those documents to somebody else's API. And dense retrieval alone misses the exact strings users are most likely to ask about verbatim — names, part numbers, clause references.

LangGraphChromaDBFastAPIWhisperPiper TTSPipecat
Results Hybrid retrieval pairs dense embeddings with BM25 so exact-term queries don't fall through, then applies MMR to drop near-duplicate passages and multi-query expansion to catch phrasings the user didn't use. One LangGraph pipeline backs the text, voice, and web front ends, so behaviour is identical across all three, and the voice path handles interruption mid-answer.

RAG · AST Chunking · Local LLM · Vector Search

AI Code Documentation & QA

Points a local LLM at a repository, splits it along the syntax tree rather than by character count, summarises every class and function, indexes them for semantic search, and writes the summaries back into the source as real docstrings.

Problem: Fixed-size chunking cuts a function in half and both halves become useless for retrieval — and raw code is identifiers, not prose, so an English question never lands near it in embedding space.

PythonASTOllamaChromaDBnomic-embed-textFastAPIStreamlit
Results Every chunk is a complete class, function, or method carrying its file path, line range, parent class, and imports. The embedded text pairs an LLM-written summary with the source, closing the vocabulary gap between a plain-English question and a code corpus. Docstring injection runs bottom-to-top so line numbers stay valid as text is inserted, and skips symbols that already have a docstring — so re-running is idempotent.

AI · Vision Transformer · Medical Imaging

Brain Stroke Detection

Binary stroke classification on brain CT scans using ViT-B/16 fine-tuned from ImageNet weights, served through a Flask app that returns a label and a probability for an uploaded scan.

Problem: Stroke signal is often a subtle asymmetry between hemispheres — a comparison across distant regions. Self-attention gives every patch a global receptive field in the first layer, where a CNN has to build that context up through stacked local convolutions.

ViT-B/16vit_kerasTensorFlow/KerasFlaskOpenCV
Results ~90% classification accuracy on the held-out set. Read that number with a caveat I'd rather state than hide: the split wasn't grouped by patient, and a CT study contributes many near-identical slices, so the figure is likely optimistic until it's re-run with patient-level grouping and reported as sensitivity/specificity — the right framing for a screening task where a false negative costs far more than a false positive.
⌥ GitHub
Deep Learning · Computer Vision · Healthcare

MURA X-Ray Classification

EfficientNetB0 transfer learning on Stanford's MURA dataset — 36,808 musculoskeletal radiographs — to flag abnormal studies for triage.

Problem: Manual radiological interpretation is slow and fatigue-prone, and MURA is labelled at the study level, so evaluating it honestly is harder than training it.

PythonEfficientNetB0TensorFlow/KerasTransfer LearningFocal Loss
Results ~64% accuracy on MURA's official, patient-disjoint validation set with the base frozen. Full fine-tuning scored 85%, but on a StratifiedKFold split of the training set taken at image level — MURA has roughly three images per study, so the same study lands on both sides. Recorded as a split-integrity failure rather than reported as the headline; the fix is GroupKFold on patient id. Class weighting, focal loss, threshold sweeping, and PR curves throughout.
